# V2 to V3 porting hazards

Status: working register; live until the V3 rewrite ships, then deleted rather than archived

## Purpose and boundary

This is the register of specific ways the Python application's behaviour could be lost, silently mistranslated, or wrongly preserved during the Rust rewrite. Each entry names the hazard and then says where it stands: addressed, with the ADR or code path that addresses it, or open, with what remains.

It is a register, not a decision record and not a contract. Nothing here establishes behaviour. An entry marked addressed is a pointer to where the real answer lives, and if this file and the code disagree, the code is right and this file is stale.

This document dies with the rewrite. Once the port is complete the porting risk it tracks no longer exists, and any entry still open by then has become an ordinary bug or a follow-up that owns itself. Delete the file rather than archiving it.

## Hazards

**Encoder boundary.** CRFty invokes the official ab-av1 CLI JSON contract and supervises FFmpeg encoding directly. ADR-003 owns the required protocol; ADR-021 owns operation containment and cleanup. The adapter requires no patched library or git dependency.

**Runtime ownership.** The former embedded library needed a dedicated current-thread Tokio `LocalSet` per job. *Retired* by ADR-003: each search runs the official CLI as a separate process that owns its own runtime, and `AbAv1Runtime` in `crates/crfty-engine/src/ab_av1/runtime.rs` runs one blocking operation at a time on a named worker thread.

**Concurrency permit.** Two concurrent operations must not share cleanup state or race for one output. *Addressed*: ab-av1's child and temp registries are now private to each CLI process, each search receives its own `--temp-dir` workspace, and `RuntimeState::try_acquire` in `crates/crfty-engine/src/ab_av1/runtime.rs` still rejects a second concurrent job within one runtime.

**Stranded children.** A cancelled or finished operation must not leave a child running, and both the graceful and the force path need proving on Windows and Linux. *Addressed*: the process supervisor terminates the operation's group or Job at leader exit or cancellation before it publishes a report, and ab-av1's own FFmpeg and ffprobe descendants inherit that containment. `cancel_descendant_and_reuse` in `crates/crfty-engine/tests/support/contract_fixture.rs` cancels a job with a live descendant, asserts the descendant stops, and asserts the runtime accepts a following job; CI runs the contract on both platforms. The [containment contract](../PROCESS_CONTAINMENT.md) owns Windows failed-spawn settlement and platform limits.

**Panic recovery.** A panic must run cancellation, workspace cleanup, and output-ledger recovery before the next job starts. *Addressed*: an ab-av1 panic is now only a failed CLI exit. In CRFty, a panicking protocol consumer is caught on its reader thread and stops the invocation, and `run_catching_panic` in `crates/crfty-engine/src/ab_av1/runtime.rs` turns an adapter panic into `JobTerminal::Panicked`. `crates/crfty-engine/src/coordinator/job.rs` routes that terminal into `abandon_output` in `crates/crfty-engine/src/coordinator/output_flow.rs`, which retires the output transaction. The contract fixture and the real-media test both start a fresh job afterwards and require it to succeed.

**Output commitment.** The application owns staging and promotion; it must never pass the input path as the encode output or delegate commit semantics to ab-av1's `--overwrite-input`. *Addressed*: ab-av1 only searches and never writes an output. `staging_path` in `crates/crfty-engine/src/output.rs` builds a sibling part file, `encode_command` in `crates/crfty-engine/src/ab_av1/operation.rs` passes that staging path to FFmpeg, and ADR-020 owns promotion as a journaled transaction.

**Process containment.** FFmpeg spawns must stay hidden on Windows and be contained strongly enough for force termination, which means validating Job Object and process-group behaviour rather than assuming it. *Addressed* by the [containment contract](../PROCESS_CONTAINMENT.md): every external tool, including the ab-av1 CLI, runs through the process supervisor on the maintained `process-wrap` frontends with Unix groups and Windows Jobs. Windows creation retains `CREATE_NO_WINDOW` and kill-on-close behaviour, and the supervisor terminates and reaps suspended children after failed setup. ADR-021 owns the operation lifecycle.

**Path fidelity.** `PathBuf` and `OsString` must survive end to end, with a defined display and hash encoding, normalized Windows verbatim paths, and validation for reserved names, trailing dots and spaces, and path limits. *Partially addressed*: `crates/crfty-engine/src/media.rs` makes `path_hash` the single origin of every `PathHash` and defines the per-platform encoding, ADR-017, keep analysis paths engine-native, holds the retention rule, and `crates/crfty-engine/src/coordinator/output_path.rs` plus `OutputTarget::validate` in `crates/crfty-core/src/job.rs` reject reserved Windows device names and trailing dots or spaces in the output suffix. Verbatim and UNC spellings are deliberately retained rather than normalized, which is a decision, not an omission. *Open and unowned*: no path-length validation exists anywhere in `crates/`, and nothing owns it.

**Scan freshness.** Racy mtime, the stat-before-and-after window, filesystem timestamp granularity, and case and Unicode path normalization all have to be explicit scan rules rather than incidental behaviour. *Addressed* by ADR-017, whose freshness table is implemented by `timestamp_reliability` in `crates/crfty-engine/src/media.rs`, which classifies exact-second, future, and recent mtimes as unreliable, and by `observation_stability` in `crates/crfty-core/src/analysis.rs`, which compares identity before and after probing. Extension matching is case-folded in `crates/crfty-engine/src/scan.rs`, and non-Unicode paths are covered by a discovery test.

**Estimation parity.** The V2 estimator's exclusive-quartile math was to be reproduced by fixtures. *Retired by decision, not addressed.* `crates/crfty-core/src/estimation.rs` deliberately uses a plain median and documents the reasoning: the type-6 exclusive quartiles and their `n >= 5` threshold existed to stabilize an interpolated spread, so reproducing them digit for digit would have frozen accidental V2 behaviour as specification. Nothing owns reproducing them and nothing should. The replacement estimator, and the shipped estimator's current unwired state, are covered by `docs/design/estimation.md`.

**Vendor management.** V2 downloaded and installed FFmpeg itself, with per-OS archives, pinned checksums, archive guards, atomic promotion, rollback, and no swap during a job. *Removed* by ADR-023, require a user-supplied FFmpeg toolchain: CRFty never downloads media tools. The engine discovers the user's FFmpeg (environment override, then Settings path, then `PATH`, with explicit tiers failing closed), verifies it with a bounded capability probe at every session start, and refuses to convert until the probe passes. Archive handling and install promotion no longer exist to get wrong; the residual hazard is a toolchain that changes underneath a running session, which the per-session probe and frozen claim revisions bound.

**Audio and decode settings.** The dead V2 audio controls must be deleted rather than ported, and the hardware-decode mapping must be ported and included in the job specification and cache matching. *Addressed*: `encode_command` in `crates/crfty-engine/src/ab_av1/operation.rs` copies every non-video stream with no audio codec or downmix, and no audio control survives in settings or the shell command surface. ADR-007, pin the actual decode mode in the analysis identity, makes the resolved decode mode part of the analysis profile and therefore part of cache identity, with resolution in `crates/crfty-engine/src/media.rs`.

**Remux failure.** Remux has to handle stream copy and incompatible subtitle streams explicitly, and a remux failure must never fall through into an encode. *Partially addressed*: `crates/crfty-engine/src/remux.rs` runs an explicit full-stream copy into Matroska, and `run_remux` in `crates/crfty-engine/src/coordinator/job.rs` maps any failure to a typed remux failure through `abandon_output`, never to an encode action, which the contract fixture verifies with a deliberately incompatible input. *Open and unowned*: there is no subtitle-specific branch. Incompatible subtitle streams are handled only by the generic stream-copy rejection, so the user sees a remux failure rather than a specific diagnosis, and nothing owns it.

**Legacy hashing.** Legacy timestamp and path hashing must exist only inside migration code, never leaking into the live identity model. A V2 path hash may become a translated observation's stored record key (ADR-025), because it names the imported record and is never compared with a live file's path hash. *Addressed*: the case-folding and verbatim-stripping normalization lives entirely in `crates/crfty-engine/src/history_import.rs` and produces the separate `ImportPath` type used only for matching imported V2 records, which is the separation ADR-015, project imported history separately, requires. Live identity comes only from `path_hash`, which deliberately performs no case rewriting.

## Retired hazard class

The V2 parser hazards do not exist under the machine protocols: carriage returns, merged stdout and stderr, log-interval assumptions, and JSON schema drift were all consequences of reading human-oriented subprocess output. CRFty reads only ab-av1's line-delimited JSON on stdout and FFmpeg's `-progress` key-value stream, and keeps human stderr solely as a redacted diagnostic. An upstream format change surfaces as a typed protocol failure, and the real-media contracts pin the supported ab-av1 release.
