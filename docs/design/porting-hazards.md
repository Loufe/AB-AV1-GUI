# V2 to V3 porting hazards

## Purpose and boundary

This is the register of specific ways the Python application's behavior could be lost, silently mistranslated, or wrongly preserved during the Rust rewrite. Each entry names the hazard and then says where it stands: addressed, with the ADR or code path that addresses it, or open, with the issue that owns it.

It is a register, not a decision record and not a contract. Nothing here establishes behavior. An entry marked addressed is a pointer to where the real answer lives, and if this file and the code disagree, the code is right and this file is stale.

## Status

Live until the V3 release. This document dies with it: once [#45](https://github.com/Loufe/AB-AV1-GUI/issues/45) closes, the porting risk it tracks no longer exists, and any entry still open by then has become an ordinary bug or a follow-up issue that owns itself. Delete the file rather than archiving it.

Owning issue: [#33](https://github.com/Loufe/AB-AV1-GUI/issues/33), the V3 rewrite umbrella.

## Hazards

**Patch surface.** The ab-av1 library patch must stay narrow and reviewable: a library target, typed encode progress, and cancellation and cleanup, nothing more. *Addressed* by ADR-003, embed a pinned ab-av1 adapter: `crates/crfty-engine/Cargo.toml` takes the dependency at a pinned git revision with `default-features = false, features = ["library"]`, the call surface in `crates/crfty-engine/src/ab_av1/operation.rs` is limited to tool paths, crf search, encode, probe, finish and cancel, and `crates/crfty-engine/src/ab_av1/mod.rs` carries a test asserting the pinned revision matches the lockfile.

**Runtime ownership.** `crf_search::run` uses `spawn_local`, so every job has to run inside a dedicated current-thread `LocalSet` rather than an ambient multi-thread runtime. *Addressed* in `crates/crfty-engine/src/ab_av1/runtime.rs`: `AbAv1Runtime::start` spawns one named OS thread, that thread builds a current-thread Tokio runtime, and `run_catching_panic` runs each job inside a fresh `LocalSet` via `block_on(local.run_until(...))`.

**Concurrency permit.** ab-av1's child and temp registries are process-global, so nothing but a mechanical permit can prevent two concurrent ab-av1 jobs from corrupting each other's cleanup. *Addressed* in `crates/crfty-engine/src/ab_av1/runtime.rs` by two layers: a process-wide `RUNTIME_ACTIVE` atomic behind `RuntimePermit` prevents a second runtime existing at all, and `RuntimeState::try_acquire` rejects a second concurrent job within one runtime. Both are asserted in `crates/crfty-engine/tests/support/contract_fixture.rs`.

**Stranded children.** A dropped or cancelled future must not leave a child in ab-av1's `process::child::RUNNING` registry, and both the graceful and the force path need proving on Windows and Linux. *Addressed* for the normal paths: `cancel_descendant_and_reuse` in `crates/crfty-engine/tests/support/contract_fixture.rs` cancels a job with a live descendant, asserts the descendant stops, and asserts the runtime accepts a following job, and CI runs the contract on both platforms. *Open residual*: [#103](https://github.com/Loufe/AB-AV1-GUI/issues/103) covers the spawn-time window where Windows Job assignment fails before an owning handle exists, which no `Drop` can currently clean up.

**Panic recovery.** A caught upstream panic must run cancellation, temp cleanup, and output-ledger recovery before the next job starts, because ab-av1 contains production unwrap and expect sites. *Addressed*: `run_catching_panic` in `crates/crfty-engine/src/ab_av1/runtime.rs` wraps the job in `catch_unwind` and cancels before returning `JobTerminal::Panicked`, and `crates/crfty-engine/src/coordinator/job.rs` routes that terminal into `abandon_output` in `crates/crfty-engine/src/coordinator/output_flow.rs`, which retires the output transaction. The contract fixture and the real-media test both start a fresh job afterwards and require it to succeed.

**Output commitment.** The application owns staging and promotion; it must never pass the input path as the encode output or delegate commit semantics to ab-av1's `--overwrite-input`. *Addressed* in `crates/crfty-engine/src/output.rs`, where `staging_path` builds a sibling part file and `OutputManager` promotes by rename, and in `crates/crfty-engine/src/ab_av1/operation.rs`, where `encode_args` passes the staging path and hardcodes `overwrite_input: false`. No ADR owns the output transaction itself, which is a gap worth closing before release.

**Process containment.** FFmpeg spawns must stay hidden on Windows and be contained strongly enough for force termination, which means validating Job Object and process-group behavior rather than assuming it. *Partially addressed*: CRFty's own spawns go through `spawn_group` in `crates/crfty-engine/src/process.rs`, which sets `CREATE_NO_WINDOW` on Windows and wraps every child in a `command_group` process group. The FFmpeg processes started inside the pinned ab-av1 dependency are not spawned by that path and are reached only through adapter cancellation. *Open*: [#103](https://github.com/Loufe/AB-AV1-GUI/issues/103) for the Windows spawn-failure window and [#87](https://github.com/Loufe/AB-AV1-GUI/issues/87) for adapter probes that run outside the child registry.

**Path fidelity.** `PathBuf` and `OsString` must survive end to end, with a defined display and hash encoding, normalized Windows verbatim paths, and validation for reserved names, trailing dots and spaces, and path limits. *Partially addressed*: `crates/crfty-engine/src/media.rs` makes `path_hash` the single origin of every `PathHash` and defines the per-platform encoding, ADR-017, keep analysis paths engine-native, holds the retention rule, and `crates/crfty-engine/src/coordinator/output_path.rs` plus `OutputTarget::validate` in `crates/crfty-core/src/job.rs` reject reserved Windows device names and trailing dots or spaces in the output suffix. Verbatim and UNC spellings are deliberately retained rather than normalized, which is a decision, not an omission. *Open and unowned*: no path-length validation exists anywhere in `crates/`, and no open issue covers it.

**Scan freshness.** Racy mtime, the stat-before-and-after window, filesystem timestamp granularity, and case and Unicode path normalization all have to be explicit scan rules rather than incidental behavior. *Addressed* by ADR-017, whose freshness table is implemented by `timestamp_reliability` in `crates/crfty-engine/src/media.rs`, which classifies exact-second, future, and very recent mtimes as unreliable, and by `observation_stability` in `crates/crfty-core/src/analysis.rs`, which compares identity before and after probing. Extension matching is case-folded in `crates/crfty-engine/src/scan.rs`, and non-Unicode paths are covered by a discovery test.

**Estimation parity.** The V2 estimator's exclusive-quartile math was to be reproduced by fixtures. *Retired by decision, not addressed.* `crates/crfty-core/src/estimation.rs` deliberately uses a plain median and documents the reasoning: the type-6 exclusive quartiles and their `n >= 5` threshold existed to stabilize an interpolated spread, so reproducing them digit for digit would have frozen accidental V2 behavior as specification. Nothing owns reproducing them and nothing should. The replacement estimator, and the shipped estimator's current unwired state, are covered by `docs/design/estimation.md`.

**Vendor management.** The vendor manager now handles FFmpeg only and needs per-OS archives, pinned checksums, zip-slip and entry-type guards, partial download with atomic promotion, rollback, and no swap while a job runs. *Addressed* by ADR-010, vendor pinned FFmpeg with checksummed atomic installs: `crates/crfty-engine/src/vendor/manifest.rs` holds per-OS pinned archives and checksums, `extract.rs` rejects traversal, absolute, cross-prefix, case-colliding, and symlink entries, `download.rs` hashes while streaming into a temp file before returning it, and `install.rs` promotes into a versioned directory and swaps the current pointer durably, so a failed install simply leaves the previous version active. The no-swap-during-a-job rule is enforced in the reducer, which rejects an install unless the session is idle with no active run. *Open residual*: [#102](https://github.com/Loufe/AB-AV1-GUI/issues/102), the pinned upstream archives no longer resolve, so a clean managed install cannot fetch them.

**Audio and decode settings.** The dead V2 audio controls must be deleted rather than ported, and the hardware-decode mapping must be ported and included in the job specification and cache matching. *Addressed*: `encode_args` in `crates/crfty-engine/src/ab_av1/operation.rs` hardcodes no audio codec and no downmix, and no audio control survives in settings or the shell command surface. ADR-007, pin the actual decode mode in the analysis identity, makes the resolved decode mode part of the analysis profile and therefore part of cache identity, with resolution in `crates/crfty-engine/src/media.rs`.

**Remux failure.** Remux has to handle stream copy and incompatible subtitle streams explicitly, and a remux failure must never fall through into an encode. *Partially addressed*: `crates/crfty-engine/src/remux.rs` runs an explicit full-stream copy into Matroska, and `run_remux` in `crates/crfty-engine/src/coordinator/job.rs` maps any failure to a typed remux failure through `abandon_output`, never to an encode action, which the contract fixture verifies with a deliberately incompatible input. *Open and unowned*: there is no subtitle-specific branch. Incompatible subtitle streams are handled only by the generic stream-copy rejection, so the user sees a remux failure rather than a specific diagnosis, and no open issue covers it.

**Legacy hashing.** Legacy timestamp and path hashing must exist only inside migration code, never leaking into the live identity model. *Addressed*: the case-folding and verbatim-stripping normalization lives entirely in `crates/crfty-engine/src/history_import.rs` and produces the separate `ImportPath` type used only for matching imported V2 records, which is the separation ADR-015, project imported history separately, requires. Live identity comes only from `path_hash`, which deliberately performs no case rewriting.

## Retired hazard class

The V2 parser hazards do not exist under crate integration: carriage returns, merged stdout and stderr, log-interval assumptions, and JSON schema drift were all consequences of reading human-oriented subprocess output. They remain relevant only if the subprocess fallback is ever revived, and upstream changes now surface as compile-time work instead.
