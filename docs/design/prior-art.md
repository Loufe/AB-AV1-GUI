# Prior art: shipped applications read against the V3 design

## Purpose and boundary

This note preserves the prior-art study behind the V3 architecture: what was read, what each codebase actually does, and which conclusion it supports or contradicts. It exists so that a decision recorded elsewhere can be traced back to the shipped evidence that motivated it, rather than to memory.

It decides nothing. Every lesson below either informs an ADR, which owns the decision, or records a possibility that was considered and declined. Where a lesson has an owning ADR, this note names it; where none exists, the lesson is evidence still looking for a decision, and that is stated explicitly.

Statements about what these projects do are source-reading findings against the pinned snapshots linked below. Conclusions about what to adopt or reject are this project's own inferences. None of this is an endorsement of the V3 design by those projects, and none of it is a criticism of theirs: each was read as a working system solving its own problem under its own constraints.

## Status

Stable reference. No owning issue. Superseded only by a better reading of the same sources.

## Handy

[Handy](https://github.com/cjpais/Handy/tree/cdbc22390987643237756382ef367f7244b2844f) was read in full as a shipped, successful analogue: the same stack and the same shape, a Rust engine around external tools, a Tauri shell, a React frontend.

- **Its best code is a retrofitted mini-reducer.** The transcription coordinator is commands-on-a-channel into a single owning loop with an explicit stage enum and `catch_unwind`. Where Handy has that structure the code is calm; where state is managed ad hoc, the patches accumulate: listener-race fallback cleanup in the model store, "optimistic update" double-mutation comments in the settings UI, roughly twenty raw string event names. That contrast inside one codebase is the strongest external evidence for ADR-002, centralize mutation in a driver reducer.
- **Pin specta exactly** (Handy pins a specific release candidate) and export bindings only in debug builds. Grounds ADR-006, generate IPC bindings with tauri-specta, which also records that Handy exports during dev runs with no freshness gate.
- **Throttle progress at roughly 100 ms with an unconditional final emit.** Independently arrived at the same flush-before-transition rule the V3 event stream uses; the coalescing contract itself lives in `docs/design/event-stream.md`.
- **A Drop guard around outcome recording** so a panic still records a terminal state. No accepted ADR owns this yet; it is one of the inputs to ADR-018 (proposed), unify job cancellation and completion, whose cancel-on-drop guards address the same failure from the supervision side.
- **Field-level settings salvage**: on a config parse failure, salvage the fields that parse and default the rest instead of resetting wholesale. Considered and declined, for the same reason settings are not migrated: a handful of values, re-entered once.
- **Headless mode skipped the single-instance plugin**, which is proof that a GUI-level guard does not protect shared engine state. Grounds ADR-008, take an engine-owned data-directory lock.
- **Tauri's exit path can swallow exit codes**, so flush and exit explicitly rather than trusting it. No owning ADR; it is a shutdown-sequence detail.
- **Per-setting IPC commands sprawl.** Handy carries more than forty commands, one per knob. This is the counterexample behind the single set-settings command under ADR-006.
- **Managers holding an app handle to emit events** couple the engine to the shell, and are the natural failure mode of "just emit from wherever". Grounds ADR-001, separate core, engine, and shell: the engine emits deltas to a channel and never sees Tauri.
- **Two trivial end-to-end tests in a successful shipping app.** This is the calibration behind treating browser end-to-end coverage as a stretch goal rather than a pillar; the testing contract is in `docs/TESTING.md`.
- **Pre-warm slow enumerations** off the critical path. Handy warms its GPU and accelerator enumeration; the analogue here is warming the vendor version check and folder enumeration in the background at startup. No owning ADR.

## HandBrake

[HandBrake](https://github.com/HandBrake/HandBrake/tree/c2a751182c855637eac7bca024698201ea4ec0d9) was read as the second reference point: the same product shape with the opposite architecture, an in-process C library (libhb) under three GUI frontends plus a CLI, twenty years old. It is a record of which decisions age well.

- **It retrofitted process isolation twice.** A token-authenticated localhost-HTTP worker process on Windows (see its [process-isolation documentation](https://handbrake.fr/docs/en/1.9.0/technical/process-isolation.html)) and an XPC service on macOS, paying for an IPC layer, port management, and health-check machinery to obtain what a subprocess engine has natively. Its parent-death handling still polls for the parent by name, with a TODO in the code. Supports ADR-001 and ADR-003, embed a pinned ab-av1 adapter.
- **Its JSON API validates the additive contract.** libhb grew a 2,300-line JSON layer to decouple frontends from C structs, and the C# frontend still hand-mirrors `hb_state_s` behind a "keep in sync" comment, which is precisely the wart specta erases. That JSON carries no wire-format version field: a decade of compatibility across four consumers rests entirely on ignore-unknown-keys plus optional-fields-with-defaults. Empirical support for the no-version-field posture under ADR-006.
- **Everything above libhb is triplicated.** Three queue implementations (roughly 3.3k, 4.4k, and 5.1k lines) with three mutually incompatible on-disk formats (two different JSON schemas and a binary NSKeyedArchiver) and drifted state enums, plus three power managers with genuinely divergent behavior. This is the counterfactual for keeping queue, session, and policy inside the engine under ADR-001. What they did centralize, preset semantics and job construction, is the one place their frontends cannot diverge, and their maintainers clearly knew it.
- **HandBrakeCLI reimplements nothing**: argument parsing plus a poll loop, everything else from the library. Evidence that a complete engine supports thin consumers, though a shipped CLI is rejected here.
- **Polling plus edge-triggered state is a lost-event machine.** `hb_get_state` silently resets WORKDONE to IDLE on read, so polling at the wrong moment loses the completion edge forever, and a sibling function with subtly different semantics deepens the trap. Push deltas plus snapshot-in-stream under ADR-006 make the class unrepresentable.
- **Error taxonomies decay.** Frontends receive a six-value error enum, the human-readable reason exists only in the log stream, and everything unanticipated lands in `UNKNOWN`. This is the argument for keeping kind, message, and stderr tail travelling together; ADR-018 is the nearest owner, and the failure-facts shape itself is engine contract rather than a decision record.
- **Log delivery by stderr-scraping**, where libhb dup2's the process's own stderr onto a pipe and fgets lines back to the frontend, is the architectural wart a typed adapter retires. One trick is worth stealing: deduplicating repeated error lines ("last error repeated N times") for FFmpeg's repetitive output, at the same sink boundary ADR-014, scrub paths inside the log sink, already establishes.
- **A cancelled encode leaves the truncated output at the destination.** Verified: there is no unlink of the output path anywhere in libhb, and nothing reclaims temp directories after a hard kill, to the point that the CLI prints "Dying badly, files might remain in your /tmp". This drove the staging-and-promotion output transaction, which is implemented in `crates/crfty-engine/src/output.rs` but has no ADR of its own.
- **Deferred validation surfaces errors at the wrong time.** `hb_add_json` stores the raw job string and parses it only at dequeue, so a malformed job fails at encode time. ADR-013, filter queue adds at enqueue, is the fix by construction.
- **Progress hygiene**: fps averaged over a roughly 3 second sliding window, ETA suppressed for the first 4 seconds. Adopted, with `Option` where HandBrake uses `-1` sentinels; the contract lives in `docs/design/event-stream.md`.
- **Pause is the shipped response to environmental pressure.** Low-disk and low-battery handling appear in the [1.3 release notes](https://handbrake.fr/news.php?peek=-21) and in the current frontends, with the exact polling mechanics read from the pinned snapshot. Noted and not adopted: machinery without a consumer at this project's scale.

The meta-lesson matches the guiding principle. Nearly every HandBrake wart is a convention that had to be remembered across four frontends, and the corresponding fix here is the same fact expressed as a type, a generated binding, or a structural boundary. HandBrake is what "invariants maintained by discipline" looks like after it succeeds anyway; every wart marks a place where discipline was the only enforcement available.

## Second study round

Eight further sources were read against the settled design: Av1an and two FFmpeg GUIs from the same domain, GitButler and Yaak as the same stack in production, Syncthing for file identity at scale, OBS for long-session resilience, rustup for vendor management, plus the xi-editor postmortem and jujutsu's operation log.

The repository links pin the exact snapshots reviewed on 2026-07-19; authored documentation and postmortems are linked directly.

- **[Av1an](https://github.com/master-of-zen/Av1an/tree/7df934db714324ae87041e17816569b2121ba27b)** (Rust, same domain): its resume checkpoint is a full-file rewrite with no fsync, no atomic rename, and multiple worker threads racing it, which is the corruption class ADR-004, persist state in an append-only journal, and ADR-009, compact the journal into a snapshot head line, eliminate. Its Ctrl-C and child-process behavior informed the cancellation work now owned by ADR-018. Its target-quality search is ahead of ab-av1's (interpolation-guided probing toward a tolerance band, percentile-aggregated VMAF), which is upstream context for ADR-003 rather than application scope, and its winning-probe reuse became a post-v3 upstream idea. Stall detection is deliberately post-v3.
- **[GitButler](https://github.com/gitbutlerapp/gitbutler/tree/517c08abdf86ab045aa0613aab607dd024b95a9d)** (production Tauri): domain crates kept Tauri-free behind a thin shell, which is ADR-001 at ten times the scale, though its own manifest questions its 67-crate taxonomy. It needed a lock-ordering doctrine, zero-sized lock-permission tokens, and a debug-mode deadlock detector, all apparatus that the single-writer driver under ADR-002 deletes wholesale. Its watcher-event guards (head-change dedupe against refetch loops, focus flushes) hand-build what a sequenced stream provides structurally. Its error convention and test kit were adopted; its invalidation-plus-refetch sync model and its codegen command layer are both recorded as rejected options in ADR-006.
- **[Yaak](https://github.com/mountain-loop/yaak/tree/0c24d6562afcb174363e7bc58182fcf123389d01)** (production Tauri): ships hand-wired string-keyed commands and events over bare ts-rs types, the papercut ADR-006 erases and lists by name. Its plugin-runtime supervision (unexpected exit becomes a notification and never a panic, bounded shutdown waits, a `CREATE_NO_WINDOW` spawn helper, `dunce` for Windows paths) confirmed adapter and porting details. It has no stall watchdog and no tree-kill because its child does not fork; ours does.
- **[Syncthing](https://github.com/syncthing/syncthing/tree/a0171e3a9b34cff897800e76fba3f8c529c7e5e8)**: a decade of change detection converged on the same size-plus-mtime trust model V3 uses, and contributed three rules now carried by ADR-017, keep analysis paths engine-native: the stat-before-and-after guard, the mtime granularity window, and case-folded cache keys. Its LevelDB to SQLite migration (throw the old store away, one-shot importer, rewrite in the current schema) is the migration posture ADR-015, project imported history separately, adopts at smaller scale.
- **[OBS](https://github.com/obsproject/obs-studio/tree/0218aa658f5bca3655f6dc4f05a9eb9a13b20c9d)**: resilience lives in artifact naming and format, not in crash-time repair. The promote-by-rename output protocol came from here, as did the crash sentinel and visibility-branched notifications. Its config durability ladder was adopted and then pared back to atomic-write-plus-`.invalid`, on the grounds that settings do not warrant the journal's recovery machinery. None of these three has an owning ADR; the journal-side corruption decision is ADR-011, acknowledge corruption by generation identity, which is a different concern.
- **[rustup](https://github.com/rust-lang/rustup/tree/c950062148fd649833012c668f0d6fd2b2ccf727)**: the vendor manager's test story and its download-hygiene rules, with its transactional-install shape pared down to two-binary scale. Grounds ADR-010, vendor pinned FFmpeg with checksummed atomic installs. One deliberate divergence: rustup's signature check is warn-only in the field, and the minisign gate here stays hard.
- **[LosslessCut](https://github.com/mifi/lossless-cut/tree/260718a5cb109115fdfc0b5ca963247327bce215)** and **[FastFlix](https://github.com/cdgriffith/FastFlix/tree/d881887456250b2c523b8ea39f8edd3eee023d81)**: FFmpeg progress-scrape folklore and the breadth of Windows file-lock retries, both recorded in `docs/design/porting-hazards.md`. LosslessCut leaves corrupt files at the destination after a kill and FastFlix cannot resume mid-encode work at all, which together validate write-then-verify and the journal. FastFlix's per-item settings snapshots produced exactly the brittleness ADR-013 records as a rejected option.
- **[xi-editor retrospective](https://raphlinus.github.io/xi/2020/06/27/xi-retrospective.html)** and the **[Jujutsu operation log](https://docs.jj-vcs.dev/latest/operation-log/)**: xi's author calls pervasive async "a complexity multiplier" and regrets the frontend/core process split. The first vindicates confining Tokio to the ab-av1 adapter under ADR-003 and ADR-018 rather than adopting an application-wide runtime; the second is the risk Tauri reimposes, contained by the one-way boundary invariants of ADR-006. jj's operation log carries concurrent-operation merging only because it admits multiple writers, a category deleted by the single-writer journal of ADR-004 plus the engine lock of ADR-008, while fold-to-sequence-N keeps jj-style restore available nearly free if undo is ever wanted.

### Follow-up encoder ecosystem review

Reviewed 2026-07-19, against the same settled design.

Av1an already covers the desired per-scene target-quality product: scene detection, interpolation-guided per-chunk probes, percentile and alternative metric aggregation, multiple workers, longest-first scheduling, probe reuse, retry, and resume. It is mature as a CLI but not yet an embeddable long-lived engine: `av1an-core` installs a process-global Ctrl-C handler per run, uses one-time global progress and resume cells, contains direct process exits, and exposes terminal progress rather than typed events. Its checkpoint files are rewritten without the journal's atomicity contract. This makes a structured contained subprocess the likely first post-v3 integration rather than a second crate commitment, and separate Analyze may intentionally be unavailable in that mode. The encoder-integration boundary itself is ADR-003.

**[xav](https://github.com/emrakyz/xav)** is the most relevant emerging Rust alternative, with native scene detection, decode and mux, chunking and resume, and target quality using CVVDP, Butteraugli and SSIMULACRA2, none of it depending on FFmpeg or VapourSynth command lines. It is valuable research and not yet a dependency candidate: no releases, a small integration surface and community, and no stable documented library contract. rust-av components such as `av-scenechange` may become useful independently, but have no v3 consumer.

Native FFmpeg bindings (`ffmpeg-next` and `ffmpeg-the-third`, `rusty_ffmpeg`, `ez-ffmpeg`) solve a lower-level in-process media problem. They would add ABI and linking constraints, unsafe FFI, platform packaging, and filter and device-context ownership, without replacing either quality algorithm. V3 instead gives application-owned FFmpeg work a focused contained process adapter using `ffprobe` JSON and `ffmpeg -progress pipe:1`, so third-party download behavior and human-readable stderr never become contracts. FFmpeg remaining an external pinned tool is the premise of ADR-010.
